# 时延预算与控制方案

## 1. 延迟敏感点

位置闭环的稳定裕度由“从真实位姿产生到飞控实际执行”的延迟及抖动共同决定。
地面站内部 CPU 计算不是主要成本；VRPN 采样、Wi-Fi 调度、ESP32 透明转发、串口
和飞控解析更可能形成长尾。

因此优先级是：

1. 消除不必要的排队。
2. 降低 Wi-Fi 和透明链路的长尾与丢包。
3. 让控制时刻和状态估计可预测。
4. 再优化微秒级计算。

## 2. 端到端预算

下表是首轮硬件测试的设计预算。各阶段分位数不能简单相加得到端到端分位数，
最终必须在飞控回显上直接统计。

| 阶段 | p95 | p99 | 测量方式 |
|---|---:|---:|---|
| VRPN 采样、服务器到地面站接收 | 10 ms | 20 ms | VRPN 时间戳 + 已同步时钟；否则仅测到达后 |
| VRPN 接收 → 控制计算 → UDP `sendto` 返回 | 3 ms | 5 ms | 地面站 `CLOCK_MONOTONIC` |
| 地面站 → ESP32 Wi-Fi UDP 单程 | 10 ms | 25 ms | 应用层序号 + ESP/飞控回显 |
| ESP32 透明桥接 + UART | 5 ms | 10 ms | 固件回显或飞控接收时间 |
| 飞控解析、校验和姿态指令生效 | 5 ms | 10 ms | 飞控时间戳 + 序号回显 |
| 飞控姿态内环反应 | 5 ms | 10 ms | 飞控内部日志 |
| 合计设计门 | **40 ms** | **80 ms** | 端到端直接统计 |

这些数字必须使用实际地面站主机、实际 AP、实际 ESP32 和实际飞控测量。开发机、
WSL、虚拟机或不同网络拓扑的数据不能作为验收依据。

## 3. 地面站内部指标门

| 指标 | 门槛 |
|---|---|
| 控制周期 | 10 ms 固定周期；p99 偏差 < 2 ms |
| 控制截止期超时 | < 0.1% |
| 位姿到达至 `sendto` 完成 | p99 ≤ 5 ms |
| 控制热路径动态内存分配 | 0 |
| 控制线程同步日志/磁盘 I/O | 0 |
| 任意内部队列长度 | 固定且不随负载增长 |
| 30 分钟无故障运行 | 无 NaN、无未处理异常、无控制流卡死 |

`sendto` 返回只说明数据已交给本机网络栈，不等于 ESP32 或飞控收到。因此还必须
记录：

- UDP 序号。
- 本机发送单调时间。
- 位姿测量时间/接收时间和样本龄期。
- 飞控回显序号、接收时间和生效时间。
- 回环 RTT、单向时延估计、乱序、重复和丢失计数。

## 4. 固定频率控制循环

基线为 100 Hz：

```text
deadline = start + n * 10 ms
sleep_until(deadline - safety_margin)
读取最新目标、最新位姿、链路健康状态
if 位姿无效或过旧:
    进入降级/失效处理，不生成新姿态
else:
    计算外环输出
    编码固定大小报文
    sendto(MSG_DONTWAIT)
发布无锁状态快照
记录控制计算耗时和截止期偏差
```

只处理最新位姿，不遍历积压样本。若多个 VRPN 样本在一个控制周期内到达，使用
时间最新且序号有效的样本，并把较早样本计入“被合并”统计。

“事件驱动、每来一帧就算一次”不作为默认方案：它把 VRPN 抖动直接传入发送节奏，
并在掉帧时缺少稳定心跳。100 Hz 固定周期同时提供控制时序和指令流活性。

## 5. 控制算法

### 5.1 外环结构

当前首版级联结构：

```text
位置目标 p_ref
            │
测量 p, 估计 v（诊断）
            v
X/Y/Z 独立增量 PID
            │
            v
X/Y 加速度 -> roll/pitch 态度；Z -> 上桨油门
航向误差 -> yaw-rate
            │
            v
GS-Link DATA_RC -> 辨识 LQR lower motor + servo 1/2/3
```

三轴均采用同一增量形式，但 X/Y/Z 的 Kp/Ki/Kd 完全独立：

```text
du = Kp*(e[k]-e[k-1]) + Ki*e[k]*dt
     + Kd*(e[k]-2e[k-1]+e[k-2])/dt
u[k] = clamp(u[k-1] + du)
```

- X/Y 的 `u` 是加速度指令，`m/s²`；Z 的 `u` 是上桨归一化油门，必须位于
  `[min_throttle,max_throttle]`。Z 映射为绝对
  `DATA_RC.throttle=2*u-1`；RC 切换基线只用于限时 bumpless 过渡，不能永久
  限制高度环的向下权限。
- VRPN 差分垂速还用于 Z 通道轻量阻尼 `-z_velocity_damping*vz`；X/Y 不增加
  额外速度环，避免重复阻尼。接管前也使用滤波垂速判断是否允许进入位置环。
- 首次激活忽略 D 脉冲；输出饱和后把积分器固定在饱和值，防止继续累积。
- X/Y 加速度按 `max_accel` 和 `g*tan(max_tilt)` 联合限幅。
- 期望机体 `+Z` 轴由水平加速度和重力确定；位置局部 `+X` 固定为机头方向。
- 输出姿态四元数只供 UI/诊断；飞控实际接收四通道手动量。

### 5.2 延迟补偿

初期默认**不启用模型预测**。只允许使用测量时间计算样本龄期，并在日志中记录。
若外环带宽确实受 10–30 ms 延迟限制，可先评估轻量外推：

```text
p_pred = p + v_est * min(pose_age, max_predict_horizon)
```

外推上限初始不超过 30 ms，且必须在轨迹和噪声测试中证明不会放大抖动。禁止在
VRPN 丢失时无限预测。

### 5.3 输出适配

控制器的语义输出与 GS-Link v1 一致：

```text
ManualControlSetpoint {
    roll      : [-1,1]  // 右滚为正
    pitch     : [-1,1]  // 低头为正
    yaw       : [-1,1]  // PX4/FRD 右偏航角速度为正
    throttle  : [-1,1]  // 映射到上桨 [0,1]
}
```

Dock 的局部 `+Y=左`、`+Z=上` 偏航为正时，heading 左转；输出前转换为 PX4
FRD 的右偏航正方向。roll 姿态在 FLU 四元数中正号本身就是右滚，不再二次取反。

**关键约束：** `DATA_RC.throttle` 是上桨集体油门，不是归一化总推力。最新
辨识 LQR 的四输出是 `[lower_motor, servo_1, servo_2, servo_3]`；上桨保持外部
所有权，不能由地面站输出五个执行器命令。

## 6. 数据新鲜度与失效策略

建议初始阈值：

| 条件 | 行为 |
|---|---|
| 位姿龄期 ≤ 30 ms | 正常控制，UI 绿色 |
| 30 ms < 龄期 ≤ 50 ms | 告警，禁止目标阶跃，UI 黄色 |
| 龄期 > 50 ms | 不生成新姿态指令，进入降级/hold 决策，UI 红色 |
| 飞控回显超过 150 ms | 地面站链路失效；飞控按自身 failsafe 动作 |
| 浏览器控制意图超过 200 ms | 释放摇杆意图；不得继续积分速度目标 |
| 四元数非法、序号回绕异常或时间倒退 | 丢弃样本并计数，不参与控制 |

这些值是起始配置，不是飞行调参建议。最终值必须根据机体动态、飞控超时、
Wi-Fi 长尾和断链台架测试共同确定。

失效时禁止做以下事情：

- 重发上一条旧姿态并假装链路正常。
- 因为 VRPN 丢失而直接发送“零推力”或任意姿态。停桨/降落只能走已经验证的
  飞控 failsafe 流程。
- 让地面站独自承担安全责任。

## 7. 链路优化

### 7.1 UDP 与 Dronebridge

主路线：

- 地面站向 `192.168.31.100:<待确认 UDP 端口>` 发送小型定长控制报文。
- 每个控制周期最多一个姿态报文；如果发送缓冲不可用，丢弃本周期并记录，不排队。
- 应用层序号用于识别丢包、重复和乱序；不为姿态做重传。
- 即使 UDP 保持报文边界，应用报文仍包含 magic、版本、长度和 CRC，便于透明
  串口侧解析。
- 透明通道不保持报文边界时，在串口前增加 COBS/长度前缀分帧；两端一致。

如果 Dronebridge 只能提供 TCP：

- 必须启用 `TCP_NODELAY`，并实测队头阻塞和重传长尾。
- GCS→ESP32 链路若 p99 超过 UDP 路线验收门，不得作为主控制链路。
- 不得通过“多发几遍”掩盖 TCP 延迟。

### 7.2 Wi-Fi 与主机

建议硬件/网络设置：

- 专用 AP 或隔离 SSID，控制期间无视频、大文件下载和互联网业务。
- GCS 优先有线到 AP；ESP32 固定 5 GHz（若固件/硬件支持）或干净的 2.4 GHz 信道。
- 固定信道和带宽，禁用 ESP32 modem/light sleep 和 AP/网卡节能。
- 保持 RSSI 和信道占用可见；低 RSSI 时告警，不静默提高发送频率。
- 记录主机 CPU 占用、网络中断、Wi-Fi 重连和 AP 邻居干扰。

### 7.3 CPU 调度

第一阶段先使用普通优先级并测量。只有控制周期 p99 抖动不达标时才增加：

- 控制线程独占 CPU 核或亲和性绑定。
- `SCHED_FIFO` 和适当优先级。
- 隔离网络中断 CPU，或调整网卡 IRQ 亲和性。
- 使用 PREEMPT_RT 内核。

任何调度优化都要用同一硬件、同一网络和同一负载前后对比，不能只凭理论。

## 8. 延迟测试方法

### 8.1 分层测试

1. **纯进程回环：** 合成 VRPN 100/200 Hz + 本地 UDP echo，记录接收至发送时间。
2. **真实 VRPN：** 静置、缓慢移动、快速阶跃，验证坐标和时间戳。
3. **ESP32 透明回环：** 地面站 UDP → ESP32 → UART 回环 → ESP32 → UDP，统计
   RTT/2、丢失和乱序；先不接飞控。
4. **飞控接收回显：** 飞控回传接收序号和时间，取得真实单向链路分段。
5. **台架闭环：** 螺旋桨拆除，验证姿态输出、超时和人工接管。
6. **系留/飞行：** 仅在门 1–5 全部通过后进行，并保持独立遥控器可切断。

### 8.2 故障注入

每项至少重复 20 次，并在 30 分钟浸泡中持续记录：

| 故障 | 预期 |
|---|---|
| 丢包 1%/5%、突发连续丢 10 包 | 不使用旧姿态；序号和失效计数准确 |
| 乱序、重复、迟到样本 | 只接受新鲜样本；迟到数据不改变当前输出 |
| 增加 20/50/100 ms 延迟 | 控制输出不排队放大延迟；按阈值降级 |
| VRPN 暂停/恢复 | 立即停止新输出，恢复后不补发历史目标 |
| 飞控链路拔线/AP 漫游 | 地面站告警；飞控在超时内 failsafe |
| 后端进程被杀 | 飞控在超时内 failsafe；无依赖地面站的补救假设 |
| CPU 满载/磁盘写满 | 控制线程仍满足截止期或明确进入降级，不静默失控 |
| 浏览器关闭/刷新 | 飞行控制不依赖 UI；速度意图释放，状态可重连恢复 |

### 8.3 数据保存

热路径只把定长记录写入无锁环形缓冲，后台线程落盘。至少保存：

- GCS 接收、控制开始、计算结束、编码结束、`sendto` 返回的单调时间。
- 位姿序号、位姿测量时间、接收时间、样本龄期。
- 飞控回显序号、飞控接收时间和执行时间。
- 控制截止期、实际周期、输出饱和、链路状态和故障位。

长时间性能结果应由固定测试场景生成，不能从 UI 截图或平均值推断。
