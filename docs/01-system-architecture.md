# 系统架构与低延迟技术路线

状态：真实 VRPN、GS-Link UDP、三轴位置 PID、速度阻尼和四通道输出已接入
适用范围：单飞行器、单动捕刚体、局域网测试飞行  
最后更新：2026-10-21

## 1. 目标与边界

地面站承担位置闭环外环，不替代飞控。位置误差由 VRPN 位姿计算，地面站产生
`roll / pitch / yaw-rate / throttle` 四通道手动量，经 ESP32-C5/Dronebridge
透明链路发送给飞控；飞控运行最新辨识 19 状态 LQI、下桨/三舵机分配和 failsafe。

首期功能：

- 接收 VRPN 刚体位姿并完成坐标变换、时间检查和有效性检查。
- 由 C++ 后端执行固定 100 Hz 的位置闭环。
- 通过 ESP32-C5 透明链路发送 GS-Link v1 `DATA_RC` 四通道。
- 为 X/Y/Z 分别提供位置 PID 参数和 WebUI 热更新。
- WebUI 三维显示机体、目标、轨迹、坐标轴、地理围栏和链路状态。
- 支持位置目标、速度摇杆、偏航目标、hold 和受保护的模式/解锁操作。
- 记录逐级时延、样本龄期、丢包、乱序、控制周期抖动和失效事件。

首期不做：

- 不在浏览器中执行控制算法。
- 不在控制数据路径中承载视频；视频会另行开通独立通路并评估 Wi-Fi 影响。
- 不让地面站直接输出电机/PWM，不绕过飞控安全策略。

## 2. 架构决策

| 编号 | 决策 | 理由 | 重新评估条件 |
|---|---|---|---|
| A1 | 位置外环在 C++ 后端固定 100 Hz 运行 | 控制时序可预测，浏览器是否掉帧不影响闭环 | 实测表明 200 Hz 能稳定降低端到端延迟且没有抖动代价 |
| A2 | VRPN 和控制链路都采用“仅保留最新值” | 旧位姿和旧姿态没有控制价值，排队只会累积延迟 | 无；仅允许显式短窗口排序，不允许长度增长队列 |
| A3 | 主控制链路使用 UDP，不做姿态重传 | 避免 TCP 队头阻塞和过期报文回放 | Dronebridge 实测只能提供 TCP 且仍满足全部验收门 |
| A4 | 阶段 1 使用 C++20 + POSIX 非阻塞 socket，自包含 HTTP/WebSocket | 当前环境零外部依赖即可构建；网络服务与实时控制线程隔离 | 进入正式发布前做安全/压力评审；必要时替换为经过审计的服务库 |
| A5 | VRPN 使用官方 `libvrpn` 独立线程接收 | 避免自行复制复杂 VRPN 协议；线程可与 UI 隔离 | VRPN 库自身处理延迟实测超过 1 ms 或无法满足需求 |
| A6 | WebUI 使用 React + Three.js，但操作热路径绕过 React 状态 | 保留界面开发效率，同时避免 React 调度进入控制路径 | 无；可将 3D 渲染替换为更轻实现而不改变后端契约 |
| A7 | 世界系和机体系统一使用右手 XYZ，`+X=前、+Y=左、+Z=上` | 单一坐标语义，机头默认 +X | 飞控适配器在边界做明确的轴映射 |
| A8 | 正式发行使用单个原生服务，WebUI 同源静态托管 | 减少代理、容器网络和额外进程带来的抖动 | 部署环境强制要求容器化时，必须使用 host network 并重新验收 |

## 3. 部署拓扑

```text
                      专用局域网 / 独立 AP

  VRPN server ──UDP──┐                 ┌──UDP──> ESP32-C5 (.100) ──UART──> FC
                     │                 │
                [Ground PC] <──HTTP/WS── [Operator browser]
                C++ backend
```

建议拓扑：

- 地面站计算主机通过以太网连接 AP，ESP32-C5 与 AP 之间使用固定频段/信道。
- VRPN 服务器与地面站处于同一低拥塞局域网；优先有线连接。
- 浏览器可以在同一主机，也可以通过有线局域网连接；浏览器位置不影响后端外环。
- 控制网络与其他视频、下载、互联网流量隔离。
- 地面站主机关闭睡眠、网卡节能和会影响 Wi-Fi/调度稳定性的后台负载。

## 4. 后端组件

```text
vrpn_source       位姿接收、时间戳检查、有效性检查、坐标变换
latest_pose       单生产者/单消费者覆盖式共享，只保存最新有效位姿
operator_target   浏览器操作意图、deadman、目标限幅与状态机
position_loop     100 Hz 三轴位置 PID、速度阻尼、姿态/油门转换、样本龄期门控
flight_codec      GS-Link v1 帧、CRC、遥测、ACK 与四通道编码
flight_transport  C5 UDP socket、序号、心跳、接收/回显、链路统计
link_supervisor   健康状态、过期策略、故障状态机
web_server        静态文件、HTTP API、WebSocket、同源访问
state_publisher   以 30 Hz 向 UI 发布最新快照，不阻塞控制线程
metrics           固定桶直方图、计数器和短时事件环
logger            后台异步落盘，禁止控制线程同步写盘
```

### 4.1 线程与调度

| 执行体 | 频率 | 职责 | 约束 |
|---|---:|---|---|
| Web I/O 线程 | 事件驱动/非阻塞 | HTTP、WebSocket、操作输入、静态文件 | 不接触实时控制对象 |
| VRPN 接收线程 | 跟踪器频率 | `libvrpn` mainloop、位姿校验、写入 latest slot | 不计算控制、不写盘 |
| 控制线程 | 固定 100 Hz | 读取最新位姿/目标、外环、编码、UDP 发送 | 无阻塞锁、无动态分配、无 JSON、无日志 I/O |
| 飞控接收线程 | 事件驱动 | 接收状态/回显、更新链路统计 | 不让接收速率决定控制速率 |
| UI 发布线程 | 30 Hz | 组装快照并广播 | 消费者慢时丢弃旧快照 |
| 日志/指标线程 | 低优先级 | 异步写盘、聚合直方图 | 不反压控制线程 |

控制线程可选设置 `SCHED_FIFO` 和 CPU 亲和性，但这必须基于实测，而不是默认增加
部署复杂度。正式服务以 systemd 管理；若启用实时优先级，通过
`AmbientCapabilities=CAP_SYS_NICE` 等最小权限方式授权，不能以 root 常驻。

### 4.2 热路径规则

1. 控制循环使用单调时钟绝对截止时间调度，禁止用“计算完再 sleep 10 ms”。
2. VRPN、操作输入和 UI 推送都采用覆盖式最新值，不允许随生产速率增长的队列。
3. 控制路径使用预分配固定大小缓冲区和二进制编码。
4. UDP 发送失败只记录计数并令链路降级，不在控制线程内重试。
5. 不做姿态报文重传；新序号替代旧序号。
6. 动态分配、字符串格式化和同步日志不得出现在控制线程。
7. 所有报文和时间检查必须处理回绕、NaN、Inf、四元数零范数和超范围值。

## 5. 坐标、时间与数据语义

### 5.1 坐标

- 世界系：右手局部 XYZ，前、左、上分别为 `+X/+Y/+Z`；单位 m、m/s、rad。
- 机体系：与飞机实例约定一致，机头 `+X`、左翼 `+Y`、机背 `+Z`。
- 位姿四元数内部统一为 `q_body_to_world`，存储顺序 `w,x,y,z`。
- 偏航角绕 `+Z` 轴，零偏航时机体 `+X` 与世界 `+X` 对齐；欧拉角只用于显示和
  人工输入。
- VRPN 原始坐标系通过配置的正交矩阵映射到 XYZ；现场单轴移动确认原始 X/Y/Z
  与地面站 X/Y/Z 一一对应，因此当前使用单位矩阵，仍包含单位换算、
  首样本 X/Y 原点和保留的 Z 高度。
- Three.js 使用独立的显示变换，不允许把显示轴修正写回控制数据。

### 5.2 时间

- 控制、网络超时、样本龄期和指标统一使用 `CLOCK_MONOTONIC` 纳秒。
- wall clock 只用于日志时间，不参与控制截止时间。
- VRPN 服务器时间与地面站时间只有在 PTP/NTP 已同步时才用于跨主机时延；
  否则保守地只计算本机接收后的处理时间，并明确标记“未测段”。
- 飞控回显地面站序号和发送时间，用于获取端到端真实时延及观察时间漂移。

### 5.3 帧率

- VRPN：推荐 100–200 Hz；首个版本按 100 Hz 基线验证。
- 控制外环：固定 100 Hz。
- 飞控姿态指令：与控制周期相同，100 Hz。
- UI 状态推送：30 Hz；浏览器以 60 fps 插值显示。
- 飞控姿态内环：由飞控决定，通常应显著高于 100 Hz。

## 6. WebUI

技术栈：Vite、TypeScript、React、Three.js。React 管理面板和低频状态；Three.js
场景用 `requestAnimationFrame` 直接更新，避免每帧触发 React 重渲染。

WebUI 职责：

- 用三维坐标系显示 XYZ 世界、机体四元数姿态、目标点、历史轨迹和围栏。
- 显示目标位置/偏航、当前位姿、样本龄期、控制周期、UDP RTT、丢包/乱序、
  当前模式和控制流状态。
- 支持数值目标、地面点击目标和手柄/键盘速度摇杆。
- 提供刚体与飞机实例绑定菜单，展示后端发现的 VRPN sensor，并支持安全热切换。
- 摇杆输入使用 click-to-toggle deadman；再次点击、再次按空格、失焦或断连后
  停止速度意图。
- 危险操作与普通操作分离；模式切换、解锁和起降能力由后端能力位动态显示。
- 页面必须显式显示“仿真 / 台架 / 真实链路”状态，防止误操作。

同源策略：

- 生产模式由 C++ 服务同时提供 `/`、`/api/v1/*` 和 `/ws/v1/realtime`。
- 开发模式使用 Vite proxy，但不得在正式部署中加入 Nginx/网关。
- 浏览器到服务器的控制意图只在持久 WebSocket 上发送，不采用逐帧 HTTP。

## 7. 安全状态机

最小状态：

```text
DISABLED -> ARMED_STANDBY -> ACTIVE_HOLD <-> ACTIVE_TRACK
                                  │
                                  ├-> DEGRADED
                                  └-> FAILSAFE
```

- `DISABLED`：只显示，不创建飞控指令流。
- `ARMED_STANDBY`：链路和位姿健康，但操作者尚未启用外环。
- `ACTIVE_HOLD`：位置目标跟随最后一次有效测量，不接收新的速度意图。
- `ACTIVE_TRACK`：操作者有有效 deadman，目标在限幅/限速范围内更新。
- `DEGRADED`：位姿龄期、链路 RTT 或丢包越界；显示告警并限制目标变化。
- `FAILSAFE`：停止发送新姿态，按已与飞控验证的策略进入 hold/land；飞控自身的
  指令超时和遥控接管优先级始终更高。

位姿龄期初值：30 ms 告警，50 ms 禁止用于新控制输出。飞控端指令超时初值建议
150 ms，但必须以台架断链试验后确定。以上阈值均为配置项，不能在飞行中无确认
调整。

## 8. 代码组织原则

- 领域类型和编解码不依赖 Web 服务实现，便于单元测试和替换传输。
- `IPoseSource`、`ICommandSink`、`ICommandCodec` 是关键替换边界。
- 仿真源、回环 sink、真实 VRPN 和真实 UDP 具有相同接口。
- 控制算法不读取配置文件，不访问系统时间以外的外部状态。
- 控制循环的输入快照携带测量时间、接收时间、序号和有效性位。
- 线协议未知时，测试使用明确标注的 `mock` codec，不能与真实飞行模式混淆。

## 9. 反对方案

- **浏览器/WASM 计算位置环：** 受 tab throttling、渲染负载和事件循环影响，
  时序不可控。
- **HTTP 轮询或逐命令 HTTP：** 连接和队头开销不可接受，且容易产生重复旧命令。
- **TCP 控制姿态：** 丢包重传会让新姿态排在旧姿态后面，增加不可预测延迟。
- **把每帧 VRPN 放入队列：** 一旦处理落后，闭环使用的是历史状态；必须覆盖。
- **用平均延迟做验收：** 闭环稳定性由 p99、抖动和突发故障决定，平均值会掩盖问题。
